What to include

Start with information that helps us investigate without exposing customer content:

  • App name and version
  • Atlassian site URL and approximate time of the event
  • Job ID, safe error code, and affected Jira item keys
  • What you expected and what happened instead
  • A content-free Evidence Package when the app provides one
Do not send secrets in the first message.

Do not include passwords, API tokens, Jira descriptions, comment bodies, or attachment contents unless we explicitly agree on a secure and necessary method.

Security reports

Use the same monitored address and put Security report in the subject. Include affected product, impact, reproduction steps, and a safe proof of concept. Do not use a public issue. Follow the testing boundaries in our Security Policy.

Read the reporting policy ↗

Support boundaries

Support is provided on a reasonable-efforts basis for the latest Marketplace version of 7thcode app behavior and documentation. It does not include 24/7 monitoring, guaranteed recovery, custom development, data restoration, legal or compliance advice, or administration of Jira and third-party services. Billing, Atlassian account access, and platform incidents may need to be handled by Atlassian Support.

If an app appears to be creating unsafe or unexpected results, stop using the affected operation, preserve non-confidential identifiers, and contact us. Customers remain responsible for backups, access controls, configuration, and review of app output before relying on it.
